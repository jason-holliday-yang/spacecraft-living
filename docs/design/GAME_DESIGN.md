# SpaceCraft Living 游戏设计文档（2026-04-10 最终定版）

## 1. 文档目的

本文档用于确认 `SpaceCraft Living` 的最终玩法设计基线。

它不再沿用旧版“`体力 + 压力 + 氧气 + 中毒条`”框架，而是正式切换为：

- `血量 Health`
- `氧气 Oxygen`
- `状态栏 Status Bar`

其中：

- `血量` 负责承伤与濒死判定
- `氧气` 负责外出时长、区域推进与路线风险
- `状态栏` 负责表达中毒、漏氧、低氧、窒息、过滤强化等持续状态

注意：

- 本文档描述的是 `补齐西线 / 南线前的最终目标设计`
- 当前实现与本设计之间的差距，请以 [`CURRENT_STATUS.md`](/Users/jason/Documents/SpaceCraftLivng/docs/design/CURRENT_STATUS.md) 为准
- 当前开发目标是在补齐西线与南线内容后冻结范围，此后不再继续扩展更大的新地图、新剧情主线或大型新玩法系统

## 2. 项目定位

### 2.1 游戏类型

`SpaceCraft Living` 是一款基于 `raylib` 的轻量级单人异星生存探索游戏，核心体验不是“硬核沙盒求生”，而是：

- 有明确目标的生存推进
- 有风险管理的区域探索
- 有持续拼合真相的调查过程
- 有资源准备的路线规划
- 有清晰提示且由玩家主动选择的多结局收束

### 2.2 核心设计目标

整个游戏要围绕以下体验展开：

- 玩家是坠毁后唯一可行动的幸存者
- 玩家要持续在 `还能继续前进多久` 与 `是否该撤回补给` 之间做决定
- 玩家要在求生推进中不断收集、拼合并验证坠毁与异星系统的真相
- 玩家对“自己为什么危险”要有一眼可读的反馈
- 玩家在终局前必须清楚知道英雄、和平、定居三条路线的差异，并理解自己是带着什么真相去做选择
- 战斗不能喧宾夺主，普通怪物更像区域性的独特威胁，而不是可反复清场的刷怪内容

### 2.3 当前版本的设计关键词

本轮设计关键词统一为：

- `两条主资源`
- `状态驱动风险`
- `区域耗氧差异`
- `营地与基地分层恢复`
- `装备改变路线，而不只是堆数值`

## 3. 核心叙事

### 3.1 故事主轴

主角是“开拓者号”飞船坠毁后的唯一幸存者。飞船 AI 助手“洛希（Loxi）”是唯一稳定的引导来源。玩家需要：

- 修复氧气、通讯、能源等关键系统
- 穿过森林、沼泽和遗迹区域
- 收集飞船日志、船员遗留记录与外星设施线索
- 在求生压力下逐步还原“坠毁之后发生了什么、这颗星球为何失稳、Loxi 的判断为何变化”
- 最终由玩家自己决定是强行求救、理解后求救，还是留在异星定居

### 3.2 叙事表达方式

叙事继续采用轻量表达：

- 主线 Objective 文本
- 通讯器中的 Loxi 提示
- 世界中的飞船日志
- 西线 / 南线调查记录与设施档案
- 关键交互点（终端、控制台、石碑、信号塔）
- 结局文本页

叙事必须满足：

- 玩家不是“顺手捡日志”，而是在外出求生时持续收集可拼接的真相片段
- 日志获取要与任务推进直接绑定：允许少数日志直接拾取，但大部分日志应在完成区域任务、设施交互或调查节点后才变为可回收内容
- 中段日志必须负责补齐人物去向、设施运行逻辑与 Loxi 判断变化，不能只做背景装饰
- 终局前玩家要能明确感到：自己掌握的信息，正在改变自己对结局的理解与选择

### 3.3 结局体系

当前目标结局结构仍维持四类：

- `英雄救援`：在飞船与 `Loxi` 确认路线后，击败 guardian 并手动激活信号塔
- `和平救援`：在飞船与 `Loxi` 确认路线后，携带 `Signal Amplifier` 稳定信号塔
- `异星定居`：在飞船与 `Loxi` 明确确认放弃求救后，选择长期生存
- `失败结局`：多次死亡后彻底失去继续生存的条件

设计要求：

- 三条成功路线都必须有清晰前置条件
- 失败应是反复失误或长期资源管理失败的结果
- 进入 Stage 7 后，玩家必须能分辨三条路线的风险结构
- 进入 Stage 7 后，玩家必须知道自己已经掌握了哪些真相，以及这些真相会如何改变路线含义
- 结局选择必须由玩家主动做出，不能被隐藏触发或误触发替代
- 终局分支点固定在飞船与 Loxi 的交互上：只有在收齐全部 log 并完成主线/支线调查任务后，玩家才能回船正式选择英雄、和平或定居路线
- 选择路线后，才进入对应的最终执行段：英雄路线继续处理 guardian 与 Signal Tower，和平路线继续准备 Signal Amplifier 与 tower 稳定，定居路线则在飞船内直接收束

### 3.4 剧情流畅度要求

为了保证最终版叙事顺畅，主线推进必须满足以下节奏：

- 玩家在飞船内部先理解“恢复、制作、提交、出门”的基础闭环
- 玩家向东进入 swamp 时，主要学会“准备不足会掉氧、会中毒、会被迫撤退”
- 玩家向西进入 Echo Wilds 时，应逐步调查失踪船员、补足“留下还是离开”的人物与情感动机
- 玩家向南进入 Subsurface Sink 时，应逐步掌握设施控制、环境改写与更深层的事故真相
- 玩家向北进入石碑与遗迹主线时，应该感觉自己是在“用前面学到的准备能力去换取终局推进”

叙事连续性要求：

- 每一阶段都必须回答“玩家为什么现在要去这个方向”
- 每次大区域切换前，都必须给出一次明确的准备提示
- 每条成功路线都必须让玩家感到“这是我主动选择的路线”，而不是误触发

推荐叙事顺序：

1. `飞船内部`：建立生存目标与基础交互认知
2. `森林`：建立安全探索与第一次外出回撤循环
3. `东侧 swamp`：建立风险管理与状态处理认知
4. `西侧 Echo Wilds`：补完船员去向、人类痕迹与定居主题
5. `南侧 Subsurface Sink`：补完设施真相、环境控制与终局准备收益
6. `北侧石碑与遗迹`：回收前面所有准备知识，进入终局抉择
7. `终局收束`：完成路线选择后的最终执行与结果确认

## 4. 核心玩法循环

游戏主循环保持以下闭环，但风险来源改由 `血量 + 氧气 + 状态` 驱动，且每轮外出都要兼顾“活着回来”和“带回新的真相”：

1. 从 Loxi / HUD / 地图获取当前目标
2. 判断当前血量、氧气与状态是否支持继续外出
3. 进入目标区域探索、采集、规避或战斗
4. 回收日志、调查记录、设施证据与船员痕迹
5. 使用装备、消耗品和地形工具降低路线风险
6. 带着关键材料与新线索返回基地制作、修复、解锁
7. 在营地或基地恢复后整理信息，并继续下一轮推进

这套循环必须满足：

- 玩家始终知道当前最大的风险是什么
- 玩家能看懂自己是因为 `掉血`、`缺氧` 还是 `状态异常` 而陷入危险
- 每一轮外出都能形成“推进一小段”的正反馈
- 每一轮外出都应让玩家多知道一点“发生了什么”或“为什么值得继续活下去”

## 5. 阶段式主线结构

项目继续采用 `Stage 1 - Stage 7` 的主线推进方式。

### Stage 1：初始苏醒

目标：

- 熟悉移动与交互
- 采集木材与金属废料
- 修复下层氧气控制台第一段

阶段作用：

- 让玩家理解“离开安全区就开始消耗氧气”
- 建立基地是完整恢复点的认知
- 奠定前期森林探索节奏
- 用飞船内部连续舱室交互，把教程自然串成一条短路线

### Stage 2：初步探索

目标：

- 获取 Glow Moss 与 Ore
- 制作 Glow Stick
- 完成氧气系统修复

阶段作用：

- 明确氧气修复的价值不是“删掉系统”，而是降低长期外出压力
- 让夜间探索开始成立
- 引导玩家完成第一次真正的“出门 -> 回来 -> 再出门”
- 把“森林是低风险教学区”这一认知彻底建立清楚

### Stage 3：深入异星

目标：

- 使用气闸控制台离开基地
- 采集 Vine / Fruit / Fungi 等中期资源
- 修复通讯中继

阶段作用：

- 开始让玩家重视路线长度与氧气余量
- 让基础食物与药用资源有稳定价值
- 让玩家理解野外风险不再只来自怪物
- 让玩家明确把东侧 swamp 视为“准备换推进”的区域

### Stage 4：危机四伏

目标：

- 使用工作台制作 Laser Gun 与 Protection Suit
- 调查坠毁线索

阶段作用：

- 强化“装备改变探索资格”的概念
- 让防护服从单纯减伤装升级为危险区必备装备
- 引入中期战斗压力与高风险区域准备
- 让剧情从“求生”转向“调查坠毁与异星异常”

### Stage 5：能源突破

目标：

- 取得 Energy Core
- 修复能源模块

阶段作用：

- 开启深层沼泽与更高耗氧区
- 让绳索、营地、过滤装备、补氧资源一起形成完整准备链
- 强化“出门前准备”而不是“出门后硬扛”
- 让玩家意识到北侧终局区不是立刻可去，而是需要先完成东侧学习线

### Stage 6：终极准备

目标：

- 收集 3 个 Relic Fragment
- 返回上层终端与 Loxi 同步终局路径

阶段作用：

- 让玩家进入真正的长路线风险管理
- 让和平路线与英雄路线在准备逻辑上拉开差异
- 让信号增幅器成为一条正当主线选择
- 让玩家从叙事上理解石碑、遗迹、Signal Tower 之间的关系

### Stage 7：终局抉择

目标：

- 收齐终局所需日志并完成西线 / 南线调查闭环
- 回到飞船与 Loxi 交互，正式进入结局分支点
- 在英雄、和平、定居三条路线中做出主动选择
- 选择后再执行对应的最终路线内容

设计要求：

- 英雄线应强调石碑准备、路线安全与 guardian 击杀后的最终执行
- 和平线应强调资源、氧气与 Signal Amplifier 装置准备
- 定居线应强调核心基础设施完成度、真相掌握度与明确确认
- 结局选择必须先在飞船内完成，不能由 Signal Tower 直接代替
- 三条路线都必须在地图方向、文案提示和资源准备上有清晰区分

## 6. 区域设计

### 6.1 飞船基地

定位：

- 安全区
- 修复中枢
- 工作台与 Loxi 交互中心
- 完整恢复点

结构要求：

- 飞船整体结构改为 `中间主通道 + 上下两侧船舱` 的布局
- 主通道承担穿行、串联和方向引导作用
- 每个船舱都必须承担一个清晰的可互动功能，不做纯装饰空房
- 玩家应能通过房间位置快速理解飞船内部功能分工

飞船舱室建议：

- `中央主通道`：承担飞船内部主路径与区域切换
- `上层终端舱`：Loxi 终端、日志归档、终局路线确认
- `上层医疗 / 支援舱`：异常缓解、临时过滤、剧情 support 点
- `下层氧气舱`：氧气控制台与基础恢复功能
- `下层制作舱`：工作台、核心装备制作
- `侧向储藏舱`：配方引导、物资说明、早期教学互动
- `气闸连接舱`：外出前最后准备点与区域出口

交互要求：

- 每个舱室至少有一个明确互动点
- 互动点必须服务于教程、恢复、推进、制作、剧情中的至少一种职责
- 不允许出现“大房间很多，但可互动内容很少”的空洞布局

承担功能：

- 早期教程
- 血量与氧气完全恢复
- 关键制作
- 主线阶段提交
- 完整异常状态清除

### 6.2 坠毁森林

定位：

- 前期探索场
- 低威胁教学区
- 低耗氧区
- 潜行和资源观察区

设计要点：

- 森林是玩家学会“安全探索”的地方，不应过度惩罚
- 这里的主要风险不是瞬间死亡，而是路线绕行、夜间视野与轻度环境干扰
- 森林潜行应继续保留，并服务于“避免不必要消耗”

### 6.3 孢子沼泽外围

定位：

- 中期资源区
- 中耗氧区
- 路线规划验证区

设计要点：

- 玩家开始真正重视 Rope / Camp / 补给品
- 风险来自更长路线、更高耗氧、更多追击与更少恢复点
- 玩家第一次明确体会“不是血快见底，而是氧气快不够”

### 6.4 孢子沼泽深处

定位：

- 高危险生存压迫区
- 高耗氧区
- 中毒与过滤系统的价值验证区

设计要点：

- 深层沼泽的主要威胁不应只是“数值更高”
- 它要同时作用于 `血量`、`氧气` 与 `状态`
- 这里是中毒、过滤、防护服、解毒资源、临时补氧的核心舞台

### 6.5 遗迹区域

定位：

- 终局区域
- 最高耗氧区之一
- 石碑 / Boss / 信号塔三者的关系聚合点

设计要点：

- 视觉和交互上必须一眼区别于普通探索区
- 遗迹应强调终局准备，而不是普通刷怪
- 石碑应显著降低 Boss 路线风险，但不应把战斗直接变成秒杀

## 6.6 世界布局

当前世界布局已经作为最终范围固定为：

- `中央偏上`：飞船基地
- `正上方`：石碑、遗迹、Boss、Signal Tower 所在的终局主线区
- `右侧`：Swamp 主风险区，承接外沼泽与深沼泽内容
- `左侧`：`Echo Wilds` 调查 / 潜行 / 船员踪迹区
- `下方`：`Subsurface Sink` 设施 / 下潜 / 真相揭示区

布局原则：

- 北侧负责主线推进与终局收束
- 东侧负责生存压力、状态系统和资源准备的主舞台
- 西侧负责人物调查、情感补强与定居路线动机
- 南侧负责设施控制、风险改写与事故真相补完
- 玩家打开地图后，应一眼看懂“基地居中、北上主线收束、东行学习风险、西行补人和选择、南行补系统和真相”的结构

实现要求：

- 现有石碑、遗迹、Signal Tower 等终局元素整体留在飞船上方
- 现有 swamp 主地图整体保持在飞船右侧
- 左侧与下方应在不抢北线主终局职责的前提下，补齐可进入区域、地标、交互点与任务链

## 6.7 地图节奏与可玩性要求

最终版地图节奏必须围绕“一个方向解决一个问题”来设计，而不是所有风险同时叠满。

区域节奏要求：

- `飞船内部`：解决教程、交互认知、恢复与制作理解
- `森林`：解决探索、潜行、回撤节奏
- `东侧 swamp 外围`：解决路线长度与部分补给价值
- `东侧 swamp 深处`：解决中毒、过滤、防护服与补氧准备
- `北侧石碑区`：解决终局信息整合与路线抉择
- `北侧遗迹区`：解决终局执行，而不是重复中段学习内容

可玩性要求：

- 每个区域至少提供一个新的风险点
- 每个区域至少提供一个新的对策点
- 每个区域至少提供一个值得回来的收益点
- 不允许玩家感觉“只是地图变大，但玩法没变”

重复性控制要求：

- 不靠增加跑路长度制造内容量
- 不靠提高怪物血量或伤害硬拉时长
- 不靠连续高压区堆叠来制造紧张感
- 新增内容必须优先增加“判断”和“选择”，而不是纯数值消耗

## 7. 生存系统

### 7.1 血量 Health

定位：

- 角色的唯一主生命值
- 统一承接原本的受伤、体力崩溃和高压后果

职责：

- 承受怪物攻击
- 承受环境伤害
- 承受中毒、窒息等持续伤害
- 作为死亡判定的直接依据

设计要求：

- 普通移动不直接消耗血量
- 普通攻击不直接消耗血量
- 血量必须让玩家一眼理解“现在危险不危险”
- 低血量应强化撤退意图，但不应一上来就强行破坏操作手感

建议阈值：

- `60% 以上`：正常
- `30% - 60%`：受伤
- `30% 以下`：重伤
- `0%`：死亡

### 7.2 氧气 Oxygen

定位：

- 游戏新的核心生存资源
- 玩家推进距离与探索节奏的第一限制器

职责：

- 决定一次外出能走多远
- 决定玩家能否安全探索危险区域
- 决定夜晚和特殊环境的压迫感

设计要求：

- 氧气必须真正参与路线规划
- 氧气不足时，应优先触发状态与行为变化，而不是简单秒杀
- 氧气在基地应完整恢复，在营地只能部分恢复

区域原则：

- 基地：稳定恢复
- 森林：缓慢消耗
- 外层沼泽：中速消耗
- 深层沼泽：快速消耗
- 遗迹：高压消耗

建议阈值：

- `50% 以下`：提示偏低
- `25% 以下`：触发 `低氧`
- `10% 以下`：触发 `窒息`
- `0%`：继续窒息掉血，而非瞬间死亡

### 7.3 状态栏 Status Bar

定位：

- 对当前所有持续状态进行统一可视化
- 不再使用独立的中毒数值条

放置规则：

- 左下角
- 位于 `血量条上方`
- `状态栏 -> 血量条 -> 氧气条` 三层排列

职责：

- 告诉玩家当前有什么异常状态
- 告诉玩家当前有什么正面增益
- 告诉玩家为什么氧气掉得快、为什么血量在持续损失、为什么现在比较安全

UI 规则：

- 使用 `图标 + 鼠标悬浮提示`
- 负面状态优先显示在左侧
- 正面状态显示在后侧
- 同类状态不重复堆叠图标，采用等级升级
- 最多同时显示 `6` 个图标

Tooltip 建议内容：

- 状态名
- 当前效果
- 触发来源
- 解除方式
- 当前等级 / 持续时间

### 7.4 首批状态设计

#### 7.4.1 中毒 Poisoned

定位：

- 状态栏中的第一个核心异常状态
- 由深沼毒雾、毒性怪物、污染残骸等来源触发

效果原则：

- 持续损失血量
- 提高氧气消耗
- 离开毒源后不会立刻消失

等级建议：

- `轻度中毒`
- `中度中毒`
- `重度中毒`

解除方式：

- 野外解毒资源：缓解或降级
- 营地：有限处理
- 基地医疗设施：完整清除

#### 7.4.2 氧气泄漏 Oxygen Leak

定位：

- 由重击、遗迹危险、设备事故等触发的异常状态

效果原则：

- 额外消耗氧气
- 可与低氧、窒息形成高压组合
- 应迫使玩家决定是否立即修补或撤退

#### 7.4.3 低氧 Low Oxygen

定位：

- 自动阈值警告状态

效果原则：

- 主要负责提示玩家进入撤退窗口
- 惩罚轻于窒息

#### 7.4.4 窒息 Suffocating

定位：

- 最致命的自动状态之一

效果原则：

- 持续损失血量
- 必须拥有最高显示优先级
- 用于制造最后抢救窗口，而不是直接秒杀

#### 7.4.5 重伤 Critical Condition

定位：

- 血量过低时自动触发的危险状态

效果原则：

- 强调角色已极度危险
- 以强反馈和高优先级提示为主

#### 7.4.6 过滤防护 Filtered

定位：

- 防护服、滤芯或特殊药剂带来的正面状态

效果原则：

- 降低危险区域耗氧
- 降低中毒累积速度
- 强化危险区可探索性

#### 7.4.7 氧气储备 Oxygen Reserve

定位：

- 便携氧气罐、应急供氧装置等带来的正面状态

效果原则：

- 形成额外的临时续航层
- 让补氧不只是“回一点条”，而是改变一次外出的最远距离

#### 7.4.8 营地休整 Camp Recovery

定位：

- 营地短暂停留后获得的正面状态

效果原则：

- 小幅回血
- 小幅补氧或降低耗氧
- 明确营地是“有限续航点”，不是完整基地

### 7.5 恢复与失败容错

设计原则：

- 基地是完整恢复点
- 营地是部分恢复点
- 三次死亡失败的容错框架继续保留

恢复职责分层：

- `基地`：完整回血、完整补氧、完整清异常
- `营地`：部分回血、部分补氧、有限缓解异常
- `消耗品`：临时止损或换取继续推进的窗口

### 7.6 平衡性底线

本项目的平衡目标不是“硬核惩罚”，而是“准备充分时明显更稳，准备不足时明显危险”。

必须遵守的平衡原则：

- 玩家每次死亡都应当能解释成准备、路线、战斗或撤退判断失误，而不是信息不足
- 任何区域都不应同时用高直伤、高耗氧、高状态叠加、长跑路四件事一起压死玩家
- 每个高风险区都要至少提供一种明显有效的对策
- 装备、营地和消耗品的收益必须足够清晰，不能做了却体感不明显

建议平衡结构：

- `森林`：轻压力、低惩罚、教学为主
- `swamp 外围`：中压力、路线管理为主
- `swamp 深处`：高压力，但有明确的过滤 / 解毒 / 补氧对策
- `北侧遗迹`：终局高压，但玩家应已掌握前面所有对策

Boss 平衡要求：

- 不允许通过瞬间过高的复合伤害把玩家直接打进“无可挽回”状态
- 石碑应降低 Boss 风险，但不应把 Boss 变成纯演出
- 和平路线的准备成本必须真实存在，但整体风险应低于英雄路线

恢复点密度要求：

- 基地承担完整恢复
- 营地承担“多一次尝试”的中转价值
- 不再通过继续拉长世界路线来制造新内容量

## 8. 资源、道具与制作系统

### 8.1 资源分层

资源建议按以下职责理解：

- 基础建材：Wood / Metal Scrap / Ore
- 生存辅助：Fruit / Glow Moss / Calm Mushroom / Special Fungus
- 区域功能资源：Alien Vine / Shell Fruit / Junk Metal / Protective Fiber
- 终局资源：Energy Core / Energy Crystal / Relic Fragment / Boss Scale

### 8.1.1 刷新与保底规则

为保证可玩性和主线稳定性，资源系统必须遵守以下硬规则：

- `飞船内资源节点` 只作为教学与首轮保底资源，默认只可拾取一遍，不参与循环刷新。
- `飞船外资源节点` 才参与刷新系统，并受刷新阈值与刷新次数上限约束。
- `Stage 1 - Stage 2` 关键主线资源必须有可达保底，不能因为刷新时机或节点分布导致主线阻断。
- 前期关键材料（至少 `Wood / Metal Scrap / Ore`）必须满足“一轮主线推进所需最小配方成本”。

这组规则优先级高于中后期细调。

原因：

- 前期被资源硬锁会直接破坏教学闭环和玩家信任。
- 飞船内资源若可无限刷新，会破坏外出探索与风险管理的意义。

### 8.2 制作系统职责

制作不是收集图鉴，而是外出风险管理工具。

关键配方对应的核心问题如下：

- `Glow Stick`：降低夜间探索信息劣势
- `Rope`：缩短高耗氧路线，改善回撤效率
- `Laser Gun`：让中后期战斗从近身冒险转为可控处理
- `Protection Suit`：提供过滤、防毒、减耗氧与危险区资格
- `Signal Amplifier`：和平路线关键装置
- `Field Camp`：野外续航与失败容错节点

### 8.3 道具映射原则

旧系统下的道具职责需要整体重映射：

- 原“回体力食物”改为 `回血 / 提升恢复效率`
- 原“减压力蘑菇”改为 `解毒 / 稳定状态 / 降低耗氧 / 临时过滤`
- 原“防护服减伤”改为 `过滤、防毒、降低耗氧、降低异常状态升级速度`
- 原“营地休息”改为 `部分回血 + 部分补氧 + 状态缓解`

### 8.4 制作设计原则

- 配方数量保持紧凑
- 每个关键配方都要明确解决一类风险
- 装备应改变探索资格，而不是单纯增加数值
- 高级制作继续绑定工作台
- 不再依赖旧版“高压力禁止高级制作”的门槛思路

制作与收益清晰度要求：

- 玩家应能从配方描述、背包说明、Loxi 提示中理解该道具解决什么问题
- `Glow Moss`、`Shell Fruit`、`Field Camp`、`Protection Suit` 的使用场景必须互相区分，不做同质化
- 如果未来只做小规模收尾型新增道具，也应优先补“新类型问题”，不要只补“更强版本”

## 9. 怪物与战斗设计

### 9.1 总原则

战斗不是纯动作爽感，而是生存决策的一部分。玩家应当：

- 知道什么时候该战斗
- 知道什么时候该潜行或绕行
- 理解击败敌人与节省氧气之间的权衡
- 理解普通怪物更像各区域的独特威胁，而不是需要持续清场的刷怪内容

### 9.2 威胁层级

- 低威胁：用于前期熟悉敌意范围与基础处理
- 中威胁：用于中期提高资源调度与装备需求
- 高威胁：用于终局准备与路线分流

当前落地约束：

- 普通怪物数量应保持克制，并固定在对应区域内承担独特威胁身份
- 终局前的紧张感主要来自路线长度、耗氧、状态压力、任务目标与真相回收，而不是连续刷怪

### 9.3 怪物伤害构成

敌人不应只造成“掉血”，而应有组合威胁空间：

- 直接伤害血量
- 触发中毒
- 触发氧气泄漏
- 逼迫玩家在路线和站位上失误

### 9.4 终局战设计

Boss 战要满足：

- 懂机制会明显更稳，但不应出现瞬间失衡的伤害跳变
- 石碑应显著降低 Boss 路线风险
- 和平路线必须是正当主路线，而不是隐藏彩蛋
- 终局压力应来自血量、氧气、状态三者的组合，而不只是高伤害

## 10. HUD 与状态信息设计

### 10.1 左下角 HUD

左下角 HUD 的目标布局：

- 第一行：状态栏
- 第二行：血量条
- 第三行：氧气条

要求：

- 一眼区分 `主资源` 与 `状态`
- 一眼分清“我是在掉命”还是“我是在掉氧”
- 一眼看懂当前最危险的问题是什么

### 10.2 状态图标规范

图标资源后续可补，但语义规则先确定：

- 同类状态使用同一主图标
- 等级变化靠边框、角标、颜色或层级表现
- 负面状态使用警示色
- 正面状态使用亮色或稳定色
- 自动危险状态应有更强提示

### 10.3 悬浮提示规范

所有状态 Tooltip 尽量统一为：

- 状态名
- 当前效果
- 来源
- 解除方式
- 当前等级 / 持续信息

### 10.4 资源刷新信息展示规范

资源刷新信息只提供“决策够用”的语义，不暴露底层实现参数。

必须满足：

- 刷新信息只显示 `可采集 / 枯竭中 / 已恢复` 三类状态。
- 不在玩家界面直接显示刷新秒数、刷新阈值、剩余刷新次数。
- 飞船内资源点标注为“一次性补给点”，避免玩家误读为可循环农资源。

设计目标：

- 保留探索和回撤策略空间。
- 避免把玩法体验变成计时器管理。

## 11. 辅助系统

### 11.1 通讯器（Loxi Interface）

职责：

- 当前阶段名称
- 当前昼夜 / 事件状态
- 当前区域
- 当前主线目标
- Loxi 的补充提示

设计要求：

- 通讯器是轻量任务卡，而不是复杂日志系统
- 提示必须和新生存系统一致
- Loxi 提示要能解释区域耗氧、状态风险与路线准备
- 通讯器必须持续强化“当前应去哪个方向、为什么去、出发前该准备什么”

### 11.2 日志系统

职责：

- 提供世界观、船员去向、设施逻辑与坠毁真相片段
- 提供轻度永久奖励
- 形成探索有回报的正反馈
- 支撑“搜集真相后自行选择结局”的核心体验

设计要求：

- 日志奖励不应压过主线装备
- 奖励更适合落在血量上限、治疗效率、过滤效率、补氧效率等方向
- 日志内容必须按调查链分层投放，至少覆盖 `飞船内部起始认知`、`西线失踪船员与留下/离开的动机`、`南线设施失稳与环境控制`、`终局前真相如何改变路线理解`
- 日志正文不能只写背景设定摘要，必须让玩家读完后理解“下一步为什么值得去做”
- 日志系统应帮助玩家在终局前形成自主判断，而不是替玩家做结论
- 大部分日志应通过任务完成、设施解锁、调查节点闭环后才能回收；只有少数基础日志允许直接拾取

### 11.3 地图系统

职责：

- 展示探索进度
- 标记玩家位置与目标位置
- 帮助玩家评估路线长度与回撤风险

地图设计要求：

- 地图要能清晰表达“北主线、东风险、西调查、南设施”的最终布局
- 地图上的飞船轮廓要体现 `主通道 + 上下船舱` 的结构，而不是单块矩形建筑
- 西线与南线在补完前允许保留施工态边界提示，但最终版本必须形成完整可玩的区域表达
- 在补齐西线与南线后，不再继续新增更大的新区域；若未来只做极小范围补充，也不得破坏当前主线区边界

### 11.4 存档系统

职责：

- 支持多槽位手动存档
- 保存核心运行状态
- 保存状态栏相关持续状态
- 对旧版本存档保持兼容或可迁移

## 12. 操作与交互基准

当前操作基线可继续保持：

- `WASD / 方向键`：移动
- `F`：交互 / 修复 / 采集 / 工作台入口
- `Space`：攻击
- `B`：背包
- `N`：通讯器
- `L`：日志归档
- `M`：地图
- `H`：帮助
- `C`：蹲伏 / 潜行
- `Z`：快速生存消耗品
- `X`：快速医疗 / 状态处理资源
- `Esc`：暂停或关闭当前界面

## 13. C 与 C++ 的职责边界

项目继续采用“玩法内核偏 C、外围编排偏 C++”的混合架构。

### 13.1 适合放在 C 的内容

- `Player` / `TaskSystem` / `GameMap` 等核心运行时状态
- 血量、氧气、状态结算
- 地图 walkability、hazard、移动阻挡判定
- 战斗、采集、阶段推进等热路径玩法逻辑

### 13.2 适合放在 C++ 的内容

- 静态内容表与文本内容
- 状态图标、状态文案、Tooltip 数据表
- 存档 schema、兼容适配、平台层
- UI 大块拆分与展示逻辑
- 高层会话、菜单、状态机编排

### 13.3 工程规则

- 公共头文件保持 C ABI 兼容
- 新增状态优先数据化，不要散落在多处条件分支
- HUD 与 Tooltip 文本尽量复用统一内容表
- 每做一轮系统迁移都补充 smoke 测试或最小验证
- 地图、飞船、剧情引导与平衡相关逻辑都必须按模块切片实现，不允许为了赶进度把新功能继续堆回单一大文件

## 14. 当前设计优先级

后续设计与开发优先级应当是：

1. 保持 `血量 + 氧气 + 状态栏` 设计稳定
2. 先保证规则表达清晰
3. 再保证阶段推进稳定
4. 再做数值平衡、表现增强和发布级收尾
5. 先完成西线 / 南线补完，再冻结地图、剧情与大型玩法范围

## 15. 本文档对后续开发的要求

任何新增机制都应先回答：

- 它影响的是 `血量`、`氧气`，还是 `状态栏`？
- 它服务于哪一阶段或哪一条结局路线？
- 它会不会让玩家更容易理解当前风险？
- 它是加强路线规划，还是只是在堆新数值？
- 它应该放在 C 还是 C++，为什么？

如果回答不清楚，就不应直接开工。

另外，任何未来保留能力还必须满足：

- 它不会破坏当前“基地居中、北上主线、东行风险、西行调查、南行设施”的整体方向感
- 它是否需要新增独立模块或内容表，而不是继续往现有大文件里追加？
- 如果它属于账号或登录类能力，是否遵守 [`../engineering/FUTURE_RESERVE.md`](/Users/jason/Documents/SpaceCraftLivng/docs/engineering/FUTURE_RESERVE.md) 的边界

并且还必须回答：

- 它是否让剧情推进更顺，而不是插入一个孤立支线？
- 它是否增加了新的判断和选择，而不是只增加耗时？
- 它会不会让平衡从“可准备的高风险”退化成“不可预判的高惩罚”？
