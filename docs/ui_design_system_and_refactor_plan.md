## 1. 当前问题与本轮方向修正

### 1.1 当前优点

- 主界面已经从纯扁平星空向有景深、有装饰结构的异星场景迈进。
- 标题、框体、按钮开始具备阴影、内框、金属边缘和符号装饰。
- 登录页已经形成“左侧世界观装置 + 右侧功能表单”的明确结构。

### 1.2 当前主要问题

1. **红色占比过高**：红月、红色雾光、红色按钮、红色框体和红色标题同时出现，使危险色失去语义，也偏离游戏中“氧气、洛希、信号、飞船系统”更适合的蓝色核心印象。
2. **设计系统未建立**：主界面使用了新风格，但读取存档、设置、暂停、地图、背包、制作、通讯器、HUD 等仍在使用旧的通用圆角面板。
3. **组件表现不统一**：同类按钮、面板、标签、状态、弹窗在不同文件中各自定义颜色与结构。
4. **界面层级不足**：大量页面仍是“一个大面板 + 多个小矩形”，缺少前景、结构框、内容层、交互层和信息强调层。
5. **危险色滥用**：红色应该保留给删除、死亡、窒息、严重受伤和不可逆选择，不应成为普通导航的主色。
6. **存在遗留界面代码**：`UI_DrawLogReader` 与 `logReaderOpen` 当前没有接入实际渲染流程，必须在重构中明确整合或移除，不能继续悬空。

### 1.3 新的总方向

整体风格定义为：

> **深空蓝色远征档案 + 异星遗迹装置 + 手绘层叠科幻**

参考《杀戮尖塔》的不是具体图形，而是以下体验：

- 有重量的菜单和框体，而不是悬浮的扁平矩形。
- 背景承担世界观叙事，菜单只占据部分画面。
- 选中、悬停和可用状态具有明显但克制的能量反馈。
- 界面像游戏世界中的某种仪器、档案或遗迹装置，而不是普通桌面软件。

## 2. 色彩设计方案

### 2.1 色彩占比

建议在普通界面中遵循以下视觉占比：

- **深蓝与蓝黑：60%–65%**，用于背景、外框、面板主体。
- **钴蓝与信号青：20%–25%**，用于选中态、能量线、导航、重要系统信息。
- **中性灰蓝：8%–12%**，用于次级卡片、禁用状态、正文层级。
- **旧金与琥珀：3%–5%**，用于标题装饰、稀有物品、目标与关键选择。
- **红色：不超过 2%**，仅用于危险、死亡、删除、窒息和不可逆操作。

### 2.2 核心色板

| 语义 | 名称 | 建议颜色 | 用途 |
|---|---|---:|---|
| 最深背景 | Abyss | `#060D18` | 全屏遮罩、最底层背景 |
| 主背景 | Deep Navy | `#091827` | 主面板、HUD 底层 |
| 次级表面 | Archive Blue | `#10283D` | 卡片、槽位、输入框 |
| 抬升表面 | Cobalt Slate | `#173A57` | 悬停、选中卡片 |
| 主强调 | Signal Blue | `#3A86C8` | 主按钮、导航选中态 |
| 高亮强调 | Loxi Cyan | `#6BCBE4` | 能量线、焦点、系统反馈 |
| 高光文字 | Ice White | `#DDF4FF` | 标题、主信息 |
| 正向状态 | Filter Teal | `#69CDB6` | 成功、过滤、恢复、已解锁 |
| 目标与稀有 | Archive Gold | `#D2AA6D` | 目标、稀有、章节、关键边框 |
| 一般警告 | Amber | `#D38C4F` | 低资源、覆盖存档提示 |
| 危险 | Emergency Red | `#B64C59` | 删除、死亡、严重危险 |
| 禁用 | Cold Gray | `#607080` | 禁用按钮、未知内容 |

### 2.3 红色削减的具体规则

- 主菜单“开始游戏”从暗红改为**深钴蓝 + 青色能量高光**。
- 主菜单背景红雾改为**蓝紫星云**，红月降低饱和度并改为冷色卫星或蓝紫月体。
- 尖塔核心改为**信号青/冰蓝**，仅在异常脉冲时短暂出现紫红色干扰。
- 登录页左侧区域改为蓝黑合金与青色档案环。
- 标题第二层不再使用大面积珊瑚红，改为冰白、浅蓝或金色。
- 普通面板的红色包边全部改为蓝钢色。
- 红色只保留在：删除账号、死亡、窒息、严重中毒、不可逆结局确认。

## 3. 视觉语言

### 3.1 材质

界面使用三种主要材质：

1. **蓝黑氧化合金**：主框架、导航、暂停和设置面板。
2. **半透明信号玻璃**：地图、通讯器、日志详情、状态提示。
3. **旧金档案铭牌**：章节标题、目标、稀有物品和关键选择。

避免所有页面都使用完全相同的圆角矩形。主框架应增加：

- 内外双层边框。
- 倒角或缺口。
- 局部金属压条。
- 细小铆钉、刻度、信号线或档案编号。
- 顶部高光与底部阴影。
- 很轻的扫描纹、磨损纹或斜线纹理。

### 3.2 层级结构

所有大型界面至少包含四层：

1. **环境层**：游戏画面、动态背景或叙事图像。
2. **遮罩层**：蓝黑渐变、景深、暗角。
3. **结构层**：外框、导航、标题区、装饰件。
4. **内容与交互层**：卡片、按钮、文本、状态反馈。

### 3.3 形状语言

- 大型面板：轻度倒角、较小圆角、厚重阴影。
- 导航标签：梯形、切角标签或机械拨片。
- 主按钮：左右轻微外扩，带能量槽或符文节点。
- 内容卡片：低圆角、细边框、选中时出现内发光。
- 危险弹窗：保留相同结构，只把信号蓝替换为危险红，避免另起一套设计。

### 3.4 动效

- 背景粒子：低速漂移，不能干扰阅读。
- 面板出现：`160–220ms` 淡入与轻微上移。
- 悬停：`100–140ms` 边框亮度和背景色变化。
- 选中：稳定的蓝色能量线，不使用持续强闪烁。
- 危险：低频红色呼吸，不使用快速闪屏。
- 地图目标：缓慢扩散环。
- 通讯器：轻微扫描线或信号波，不做高频噪点。

## 4. 排版与信息层级

### 4.1 字号基线（1440×900）

- 游戏主标题：`52–72px`
- 页面标题：`30–36px`
- 分区标题：`22–26px`
- 卡片标题：`17–20px`
- 正文：`15.5–18px`
- 元信息：`12–14px`
- 键位标签与徽章：`10–12px`

### 4.2 排版规则

- 中文标题不强制全大写语气，英文可使用小型大写档案风格。
- 正文必须保证中英文都能完整换行。
- 主信息使用冰白，次级信息使用灰蓝，提示使用信号青。
- 金色只用于“值得注意”，红色只用于“有危险或不可逆”。
- 同一页面最多出现三种主要文字颜色。

## 5. 统一组件系统

在重构具体页面前，先建立公共组件，避免继续在各文件中复制颜色和绘制逻辑。

### 5.1 主题令牌

建议新增：

- `include/ui_theme.h`
- `src/presentation/ui/ui_theme.cpp`
- `src/presentation/ui/ui_components.cpp`
- `src/presentation/ui/ui_components_internal.h`

主题至少包含：

- 背景、表面、边框、文本和语义颜色。
- 标准间距、圆角、边框厚度、阴影偏移。
- 标准字号和行距。
- 动画持续时间和透明度。

### 5.2 公共组件清单

1. `UI_DrawScreenScrim`：全屏遮罩和暗角。
2. `UI_DrawArchiveFrame`：大型档案框架。
3. `UI_DrawPanelHeader`：标题、编号、副标题、关闭提示。
4. `UI_DrawNavTab`：普通、悬停、选中、锁定状态。
5. `UI_DrawActionButton`：主操作、次操作、危险、禁用四种类型。
6. `UI_DrawInputField`：默认、焦点、错误、禁用状态。
7. `UI_DrawContentCard`：列表卡片、物品卡片、存档卡片。
8. `UI_DrawDetailPanel`：右侧详情区。
9. `UI_DrawBadge`：数量、分类、状态、键位。
10. `UI_DrawDivider`：普通、档案、危险三种分隔线。
11. `UI_DrawScrollbar`：通讯器、日志和详情滚动。
12. `UI_DrawTooltip`：状态、地图图例、物品说明。
13. `UI_DrawModal`：普通确认、危险确认、结局确认。
14. `UI_DrawEmptyState`：未解锁、无存档、无日志、无物品。
15. `UI_DrawProgressMeter`：生命、氧气、音量、任务进度共用基础结构。
16. `UI_DrawKeyHint`：键盘和鼠标提示。

### 5.3 组件状态必须完整

每个交互组件必须同时实现：

- 默认。
- 鼠标悬停。
- 键盘/手柄选中。
- 按下。
- 禁用。
- 错误或危险。
- 锁定。

- 按移动、探索、战斗、生存、界面五个分组展示。
- 键位使用统一键帽组件。
- 重要生存提示使用蓝色或琥珀，不使用普通白字堆叠。

### 6.6 HUD 与即时反馈

#### F01 生存状态主面板

- 文件：`src/presentation/ui/ui_hud.cpp`
- 当前内容：状态栏、生命、氧气。
- 新设计：更紧凑的蓝黑生命支持模块。
- 氧气是本游戏核心系统，应在视觉上比生命更突出。
- 生命正常状态不使用大面积红色；仅低生命时逐渐转向红色。

#### F02 生命条

- 正常：冷白/蓝灰。
- 受伤：琥珀。
- 危急：危险红。
- 避免常态生命条始终为高饱和红色。

#### F03 氧气条

- 主色：信号青与冰蓝。
- 低氧：蓝色闪烁转为琥珀警告。
- 窒息：边缘红色脉冲，但条本身仍保留氧气语义。

#### F04 状态栏与状态提示

- 文件：`src/presentation/ui/ui_hud_status.cpp`
- 正面状态：青绿色。
- 环境/系统状态：蓝色。
- 一般负面状态：紫色或琥珀。
- 致命状态：红色。
- 溢出状态、持续时间和悬停详情使用统一状态卡。

#### F05 快捷入口

- 文件：`src/presentation/ui/ui_hud_shortcuts.cpp`
- 地图、背包、洛希、快速使用。
- 圆形按钮调整为更有结构的仪器节点。
- 必须显示键位或至少在悬停时显示名称。
- 当前没有传达标签内容，应恢复标签或增加悬停提示。

#### F06 HUD 消息

- 当前中央消息面板使用固定金色边框。
- 按消息类型分为：信息、获得、完成、警告、危险。
- 普通信息使用蓝色，任务完成使用青绿色，警告使用琥珀，危险使用红色。

#### F07 全屏危险反馈

- 低氧、窒息、危急生命的屏幕脉冲应区分。
- 低氧以冷蓝收缩和轻微暗角为主。
- 窒息才叠加红紫色边缘。
- 避免整个屏幕频繁高亮。

### 6.8 死亡、结局与不可逆选择

#### H01 死亡弹窗

- 文件：`src/presentation/ui/ui_menu.cpp`
- 这是允许大面积使用危险红的页面之一。
- 仍需保留蓝黑框架，使其属于同一套 UI。
- 按钮：重新开始、读取、返回菜单，读取不可用时显示原因。

#### H02 结局路线选择

- 文件：`src/presentation/ui/ui_menu.cpp`
- 英雄路线、和平路线、定居路线应使用三种语义强调色：
  - 英雄：冰蓝/亮金。
  - 和平：青绿/浅蓝。
  - 定居：紫蓝/旧金。
- 取消为灰蓝。

#### H03 路线二次确认

- 不应全部使用危险红，因为这是重要选择而非错误。
- 使用深蓝框架、金色标题、琥珀不可逆提示。

#### H04 结局总结页

- 文件：`src/presentation/ui/ui_ending_panel.cpp`
- 包含背景图、结局标题、总结文本、得分、徽章、遭遇记录和菜单操作。
- 四种结局共用结构，不同结局只改变背景图、强调色和局部装饰。
- 失败结局使用危险红；其余结局不使用红色主框。

## 11. 建议的首个执行批次

下一轮不应直接从地图或背包单点修改，而应按以下顺序开始：

1. 先完成主题令牌与公共组件。
2. 使用新组件重新调整主菜单和登录页，解决红色过多问题。
3. 立即重构读取存档、设置和暂停，使前端与系统菜单形成第一套完整闭环。
4. 在这套组件稳定后，再进入地图、背包、制作和洛希通讯器。

这样可以避免每个页面重复实现一套边框、按钮和颜色，保证后续所有界面真正统一。

## 14. 依赖关系与实施约束

### 14.1 不应跳过设计系统直接改页面

地图、背包和通讯器包含大量卡片、标签和状态。如果没有先完成公共组件，会产生第三套、第四套临时按钮和面板，因此：

- Phase 1 是后续所有页面的硬依赖。
- Phase 2 是设计系统的首轮实战验证。
- Phase 3 完成大型面板外壳后，Phase 4–6 才能并行推进。
- HUD 可以在大型面板稳定后单独推进，但必须复用语义颜色和状态组件。
- 叙事与结局最后收口，以避免前面组件仍在变化。

### 14.2 数据与视觉分离

重构过程中遵守：

- 不修改任务、存档、地图揭示、物品数量和结局判定逻辑。
- UI 文件只消费现有数据，除非某种展示确实缺少必要字段。
- 页面绘制逻辑与交互矩形必须同步修改。
- 新增动画状态时集中管理，不把大量静态局部变量散落在绘制函数中。

### 14.3 资源策略

优先级如下：

1. 先使用 raylib 图元完成组件结构和动效。
2. 需要纹理质感时，再加入小型可复用资源：噪声、扫描纹、九宫格框体、角饰。
3. 不为每个页面单独制作一张不可复用的大背景。
4. 不直接复制《杀戮尖塔》的图形、纹理或构图资源。

## 16. 方案结论

本次界面重构的重点不是把所有面板都加上更多装饰，而是建立清晰、可复用的视觉语义：

- **蓝色代表洛希、氧气、信号、系统和可交互状态。**
- **青绿色代表恢复、成功和稳定。**
- **金色代表目标、档案价值、稀有和重要选择。**
- **琥珀代表资源压力和需要谨慎的操作。**
- **红色只代表真正的危险、死亡、删除和不可逆损失。**

按照本计划完成后，主菜单、弹窗、地图、背包、制作、通讯器、HUD、剧情和结局不再是互相独立的页面，而会共同组成一套完整的“洛希远征档案”界面系统。
