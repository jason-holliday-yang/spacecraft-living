## 资源策略

项目继续采用可选资源加载模式：

- 有文件时优先加载外部资源
- 缺失文件时自动回退到程序化绘制或静音
- 资源缺失不会阻止主程序运行
- 当前已复核图片资源路径解析与加载链路，没有发现“文件存在但加载失败”的系统性问题

## 下一轮资源重点

根据最新地图与剧情设计，后续资源补充应优先围绕以下方向，而不是继续零散补图：

- `飞船内部重构`
  需要体现 `主通道 + 上下船舱` 的结构差异与舱室功能差异
- `北侧石碑 / 遗迹主线区`
  需要更清晰地区分“普通遗迹地块”和“终局主线空间”
- `东侧 swamp 细化`
  需要增强外沼泽与深沼泽在视觉、音频和交互上的层次差别
- `西线 / 南线第二轮剧情资源`
  需要补齐 `W4-W5`、`S4-S5` 的剧情图、场景图和终局反哺图
- `日志剧情图全覆盖`
  需要把日志剧情图从当前 `3` 张扩展到与游戏内全部 log 数量一致，并确保每张图都承担对应日志的剧情推进表达，匹配“多数日志通过任务/交互解锁”的新推进方式
- `视频演出规划`
  先完成清单与命名规范，待播放系统接线后再转生产

## 维护原则

- 新增资源时，先确认代码是否真的会主动加载它
- 如果只是把文件放进目录，但没有代码接线，不要在文档里写成“已完成”
- 如果代码开始加载某个文件，必须在同一轮同步更新对应 README
- 如果只是新增了剧情资源命名方案、AI 出图提示词或目录规划，要明确标注为“规划中 / 未接线”
- 文件名保持 ASCII，严格区分大小写
- 规划中的资源必须和“当前已接线资源”分开记录，避免误判完成度
- 日志相关资源文档必须同时记录两件事：`当前已接线数量` 与 `目标应补齐到每篇 log 一张图`，不能只写其中一边
- 如果剧情推进规则改成“日志驱动”或“回船确认路线”，相关资源 README 也必须在同一轮同步更新
